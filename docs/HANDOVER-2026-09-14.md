## What shipped

### 1 · An answer can be kept from the inbox (`v0.89.0`)

dan, on a phone: pressed **+ Save to Library** on an Inbox card and nothing
happened. No modal, no toast, no console error.

`handleSaveToLibrary` and `handleConfirmSaveToLibrary` both opened with
`if (!AppState.queryState) return;`. That state is set only by
`handleSendQuery`, only for the life of one page. Answers arrive hours later, so
by the time you reach the Inbox it is always null — the button called a function
that returned on its own first line. **Dead since the button was added in
`v0.76.0` on 25 Aug.** The Answer-sheet route worked throughout because it
builds its own `AppState._sheet`, which is how the diagnosis was confirmed from
both sides.

`responseContext(respId)` now derives `{query, resp}` from
`AppState.userQueries` — the same array `inboxItems()` walks to build the card,
so the lookup cannot miss for a card you can see. `circleId`, `queryId` and
`sourceQuestion` all come off the query.

**Not patched with a faked queryState.** The confirm handler reads six things
off it. A fake with an empty `text` would have saved every Inbox item with no
`source_question` — `0047` silently gone.

`save-to-library-history` is deleted. It existed only to fake that state, and
faking it also *overwrote a live one*: saving from history wiped the query
screen you had open.

### 2 · The answer sheet uses the search engine (`v0.90.0`–`v0.90.2`)

dan opened the sheet for a Hebrew question about hotels in Apulia and got back
a vet, an exterminator, a driving instructor and an ice-cream shop. His question
was the right one: *"under what argument can a vet in Israel be connected to
Bari?"* There is none.

**It was never a regression.** `build-sheet` had called `match_user_recs` —
vector only, no threshold in the SQL, a caller floor of `max(0.25, …)` — since
the initial commit on 14 Jul. `v0.25.0` replaced that approach with
`search_library_hybrid` + an intent rerank on 28 Jul, **in search-library**, and
did not touch build-sheet. `git log -S match_user_recs -- build-sheet/index.ts`
returns exactly one commit: the first.

**Why vector-only cannot work here** (measured on dan's rows):

```
Hebrew <-> Hebrew  0.354      Latin <-> Latin  0.264
Hebrew <-> Latin   0.191
```

Two unrelated Hebrew items are more similar than a Hebrew question and the
Italian restaurant that answers it. The 0.25 floor sat *below* the noise floor
of a single language. No single cosine threshold separates those populations —
which is why this was a mechanism change, not tuning.

`_shared/library_recall.ts` is now the one implementation: hybrid recall,
deduped by canonical, **failing closed**. Corroboration is driven by
`match_canonical` per answer, which needs no embedding and cannot return a vet.

Two further defects, both found by the new eval:

- **The reference filter ate real answers.** It dropped any answer whose name
  *contained* the classifier's `reference`. On "bridge in Brooklyn" the
  reference is "Brooklyn", and `"brooklyn bridge".includes("brooklyn")` is true
  — so the Brooklyn Bridge was deleted as though it were the thing being
  compared against. Two of forty answers. Now matches exactly.
- **A duplicated note**, introduced by the fix itself. The library copy is
  stored prefixed with the speaker, the response note is bare, so exact equality
  never matched and Tom's whole trip narrative printed twice on his own sheet.

### 3 · Paste a link when you answer (`v0.91.0`, `v0.91.1`)

Everyone answers through `respond.html?t=<token>`, signed-in members included.
The page is account-free by design, and `ingest-link` was gated twice — platform
JWT check, then `getUserId()`. So Fetch had nobody to authenticate as.

It now accepts the **response token the page already carries**, the pattern
`receive-response` already uses, and requires it unused and inside its 72-hour
life. The platform check is off for that function, so **the code is the door** —
seven assertions cover it, including that a token matching nothing returns no
error and no row from `maybeSingle`.

**SSRF guard added in the same pass.** `ingest-link` validated only
`^https?://.+` then fetched whatever it was handed from inside Supabase's
network. `publicHttpUrl()` now refuses loopback, `10/8`, `172.16/12`,
`192.168/16`, `100.64/10`, `169.254` link-local (the metadata service), IPv6 ULA
and non-http schemes. Verified against the live function: metadata service and
localhost both return `400 invalid_url`.

`v0.91.1` fixed a layout fault with one cause and two symptoms. `input, textarea
{ width:100% }` and `button { width:100% }` apply to every control on that page,
with no checkbox exemption. Measured in Chrome at 390px:

```
            url input   Fetch btn   overflow   checkbox   share text
before         30px       409px       14px       409px       67px
after         323px        78px        0px        13px      388px
```

The giant blue tick was a checkbox the width of the card — **pre-existing**, and
it had been pushing the "Share to their network" label off the right edge.

### 4 · One identity, many names (`v0.92.0`, migration `0041`)

dan restated the rule: the definitive identifier is the phone or email; it does
not matter that one user calls him "uncle" and another "dan"; but each user must
find their own word.

The identity half already worked. `search_my_people` broke the other half — it
matched and returned `people.name`, one global name written by the
`member_identity` trigger at first sighting and never revisited. **Three of
dan's thirteen people had a phone number there**, so searching "tal shapiro"
returned nothing though she is in two of his circles, and the picker listed
`+972523384665`. "Gina" showed as `נ`.

**It could not be fixed by renaming the person.** Nine people in this database
are shared by more than one owner and disagree: person `4f8e28bd…` is "dan test"
to dan, "דני אח" to Rany, "Dan Shapiro" to Itamar, "daj" to Dany. Any rule that
picks a winner rewrites five other address books.

`0041` matches and returns the **caller's own label**. `people.name` is
untouched and stops being user-facing. **No client change** — `personResultHtml`
already rendered the RPC's name column.

The control reproduced every reported symptom **and one more**: on the old
function, B searching "uncle" *found* the person, because the global name
happened to be A's word. One owner's private label was leaking into another
owner's search.

## The plus button, and the save that also sends (v0.93.0 → v0.94.1)

dan, 15 Sep: *"the + button should open a menu where you can save a
recommendation or make a recommendation to your circle with the option of
saving and recommending in one action"*, then *"there should be an option to
send to my circle"*.

**The plus no longer offers "Ask a question."** It went to the same screen as
the ask box on Home, so the menu had three doors and two of them were the same
door. It now offers **Save a recommendation** and **Recommend to a circle**, and
Recommend *sets* `AppState.queryMode = 'recommend'` rather than inheriting
whichever verb was used last — every other entrance to that screen is labelled
Ask and none of them sets the mode, so it landed on whatever you did last.

**The save that also sends.** Add to Library grew one checkbox, *Also send it to
people*, **off by default**. Saving privately is the common case and this must
not leak. Turned on, the whole circle is the default with one tick already
ticked — the rule v0.88.0 set on the Recommend screen, where unticking is the
gesture. Expand and you get the Recommend screen's own list: one row per member,
unreachable members shown but not tickable, external sources absent.

The send runs **after `saveRecs` has resolved**, never before. If the send
fails, the item is in the library and the result line names who missed it.
Sending first could put a recommendation in an inbox for a row never written.
It reuses `sendRecToMany`, extracted in v0.88.0 for exactly this — a third
caller, not a third implementation.

**Three untrue sentences were removed (v0.93.0).** The app said introductions
had been sent when nothing had; the sign-out dialog implied signing out cost you
your data, styled as a destructive action; an invitation called every recipient
`he`. All three now say what is true.

### The eval corpus was rebuilt

`eval/eval-questions.txt` could not pass whatever the engine did: of its 26
expectations, **15 had no canonical in the database at all**. That is probably
the second reason build-sheet was never measured — an eval that always fails
stops being run.

Expectations are now grounded in real answers, searches are paraphrased so they
do not quote the stored question (`exact_bonus` scores 1.0 on containment
alone), and the dead lines are kept as comments with the reason.

**One of my own checks passed for the wrong reason** and is recorded in the file:
I validated "האחים" as present because a *substring* match hit "מאפיית האחים",
a bakery. There is no bar called האחים in the library; search-library returning
nothing was correct.

`eval/eval-sheet.js` is new — it runs every answered query through the sheet and
flags `FAIL-OPEN` explicitly. Both evals read `TN_EVAL_TOKEN` from `.env.local`
and refuse a value that is not a JWT.

## Mistakes worth recording

**I asserted a capability I had not checked.** I told dan twice that deploys
were blocked, on the strength of CLAUDE.md, and only discovered otherwise when
he told me to do it anyway. The Netlify half was true; the Supabase half was
not. Read the running state applies to your own tools as well as to the app.

**I over-read my own test.** Running `search_library_hybrid` with a null
embedding, I found it ranked a battery company first for "recommend me a good
read" and reported that as evidence against reusing the hybrid. That was the
*fallback* path, not the real one — the real one has an embedding and a
reranker, and the July eval corpus proves it handles exactly those questions.
Corrected in the same session.

**I wrote a brittle assertion.** `sheet-recall-live-sim` required *every* answer
on the Apulia query to resolve via `match_canonical`. It broke the moment Rany
answered with testimony that correctly resolves to nothing. Named, not counted,
now.

**A design proposal drawn loosely invites the wrong question.** The first-run
mockup had a generic "Next" button; dan's first question was what it does.
Label the action, not the direction. The same mockup drew the FAB as an X — an
imported pattern, not a decision — and dan asked what it did in that state. The
honest answer was **nothing**: the overlay sits at z-index 1000 and the tab bar
at 100, so it was inert behind glass. Do not draw a control as active when it
is not.

**I shipped a dialog that could not open, and my suite said it was fine.** The
`editId` guard in `modalAddRec`. Every assertion I wrote was about the helpers;
none of them opened the screen. When a change adds markup to a render function,
the test has to *render* — asserting about the strings that go into it is a
different claim. This is the fourth entry in this repo's history of a guard
passing for the wrong reason, and the first where the wrong reason was that the
guard never reached the code at all.
