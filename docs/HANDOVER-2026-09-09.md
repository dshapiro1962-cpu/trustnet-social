## The 9 Sep state check — what two idle weeks show

The app was not used between 26 Aug and 9 Sep except once. That makes the few
things that did happen unusually clean evidence.

### The answer loop ran unattended, and correctly

On **3 Sep 02:01** one answer arrived with no one watching:

```
question   "Good restaurant in Firenze?"
name       Trattoria Dalla Lola
kind       restaurant
location   Florence, Italy
verified   false
saved_to_library  false        handled_at  null
```

Three fixes are visible in that one row:

- **The question framed the answer** (`v0.74.1`). "Firenze" resolved to
  "Florence, Italy" — a lookup normalising what a person said.
- **Recognition is not invention** (`d35430b`). `verified` is `false` — no web
  evidence was found — and the location was **kept anyway**. The over-broad
  anchor guard I wrote on 24 Aug would have blanked it.
- **The inbox is honest** (`0046`). `saved_to_library` is false and
  `handled_at` is null, which agree with each other. Before `0046` these could
  disagree and the inbox showed a live Answer button for a dealt-with item.

Nothing else was created. 153 canonicals, unchanged since 25 Aug.

### The sweep schedule is found — it is pg_cron, and it is alive

The last three handovers said "something runs the sweep but nothing in the repo
schedules it". It is a **pg_cron job in the database**:

```
jobid 1   jobname suggest-sweep   schedule */5 * * * *   active true
command:  select net.http_post(url := '<project>/functions/v1/suggest-sweep',
                               headers := <service_role bearer>, body := '{}')
```

**Measured:** 8,328 successful dispatches, most recent five minutes before this
was written. It is not going to vanish silently — but it is still not in the
repo, and it is invisible to anyone reading only the migrations.

**Do not commit it verbatim.** The `command` embeds the **service_role JWT in
plaintext**. A migration that recreates this job must read the key from Supabase
Vault, not carry it in git.

### NEW — one in three sweep dispatches times out

`cron.job_run_details` says "succeeded" for every run, but that only means
`pg_net` accepted the request; it is fire-and-forget. The actual HTTP outcomes
are in `net._http_response`:

```
window 2026-09-09 01:20 → 07:15   (pg_net keeps a short retention)
72 dispatches:  50 × 200        22 × "Timeout of 5000 ms reached"
                                 30.6% timing out
```

The timeouts are all at exactly `pg_net`'s 5,000 ms client limit, with the time
spent in the request itself (DNS and handshake are single-digit to ~250 ms).
**This is on an idle database with nothing for the sweep to do**, so it is
baseline latency — most likely Deno cold starts — not workload.

What this does **not** prove: that those invocations failed. `pg_net` giving up
at 5s does not stop the edge function server-side, and the function's own logs
are not readable from this machine. The sweep's design already tolerates it —
the watermark only advances on a clean run, so a lost run is retried rather than
skipped.

Why it matters anyway: at beta volume the sweep will have real work to do and
will get slower, not faster, and a caller that gives up at 5s will hide whether
it is finishing. Raise `timeout_milliseconds` on the `net.http_post` call when
the schedule goes into a migration.

## What shipped, 25–26 Aug

### 1 · The inbox knows what has already been dealt with (`v0.76.0`, `0046`)

dan, with a screenshot: *"this stayed in the inbox after being answered — when
you press the answer button you get link expired"*, and then: *"the same happens
with answers, they stay in the inbox as not saved with the toggle save to
library active"*.

Two facts about one event lived in two places and disagreed. The respond flow
wrote `query_responses`, the inbox read `notifications`, and nothing joined
them. `0046` adds `notifications.handled_at`, backfills it, and adds a
`mark_response_saved()` RPC that the client calls and **asserts returns true** —
`saveQueries` used to write and hope.

### 2 · One item, one set of facts (`v0.76.1`) and the field contract (`v0.78.0`)

Cards disagreed with each other about the same item because `loadUserData`
returns camelCase and PostgREST embeds return snake_case, and each render
function coped in its own way. `canonFacts(can)` normalises both into one shape;
`itemFactsText(can)` is what every card now calls.

`v0.78.0` is the rule that stops it recurring, written above `canonFacts`:

```
canonicals.kind              WHAT THE THING IS      → affordances
canonicals.category          what the owner typed   → display
recommendations.category     YOUR category (0045)   → display
canonicals.primary_category  ONE OF EIGHT, SHARED   → matching
DISPLAY reads category || kind. AFFORDANCES read kind.
MATCHING reads primary_category. Never crossed.
```

Five of the seven bugs in that session were one field being asked two questions.
This is why the "start from scratch with a proper design" option was argued
against: the causes live in the schema and would have survived a rewrite.

### 3 · Affordances follow what a thing is (`v0.78.1`)

A pair of ski boots offered "Get directions". The card had one code path and it
assumed a place. `itemFindLinks(can, rec, circle)` now routes on `kind`, with a
hard rule: no location means it is a thing, or a person with no address, and the
link becomes "Find to buy".

### 4 · A circle is only as broad as its owner made it (`v0.79.0`)

A **beach in Leros** reached dan through his **ski** circle. `INTEREST_ALSO`
widened `ski → [ski, destination]`, which is right when classifying an *item*
and wrong when deriving a *circle's* interests: it silently put `destination`
on the circle, and destination lets any place through.

`interestsForKind(kind, widen)` — item classification widens, circle derivation
does not. The seeding function repairs **only** circles whose confirmed set
exactly equals the old widened derivation, with nothing custom and nothing
declined. It does not touch a set a person has edited.

### 5 · A circle with a place only takes things from there (`v0.80.0`, `0048` in the sweep)

dan: *"dshapiro8@hotmail.com has no leros circle... and even worse the reason
the app gives"* — a seafood restaurant in **Greece** arriving through a circle
named **Italy**, explained as *"You share Italy, which is about restaurants."*
True on type, absurd on place.

`circles.location` had existed all along, **populated on 0 of 30 rows**: the
client loaded it into state and never wrote or showed it, and the sweep never
read it. The same dead-flag shape as `verified` and `kind` before them.

`placeFits(circleLoc, itemLoc)` — both sides must have a place for the gate to
apply, so a circle with none still accepts from anywhere and an item with none
(a book, ski boots) is never excluded for lacking an address it could not have.
Containment either way.

**`v0.80.1`** folded the field away after dan said *"the change you made make
where a compulsory field in a way"*. It is a `<details>` that opens only when a
place is already set — a restriction in force must not be hidden behind a fold.

### 6 · The beta marker (`v0.81.0`)

dan: *"put somewhere on the home screen the fact that its a beta, not at the
bottom of the scroll, most important that it will be visible on a phone"*.

The version marker had by then been in three places, each unreadable on the
device it was checked on: `#sidebar` (hidden under 768px), Profile (its nav
entry sits under `#mobile-tabbar`), and the foot of `renderHome()` (needs a
scroll). `#beta-strip` is a sibling of `.topbar` inside `#main`; both are
`flex-shrink:0` and `#view-body` is the only element that scrolls.

It carries `APP_VERSION`, so `#home-version` was **removed** rather than kept —
two copies of one fact is how they drift. It pads for `safe-area-inset-top`,
because `apple-mobile-web-app-capable` is `yes` and a home-screen install would
otherwise put the whole strip under the status bar.

### 7 · A migration runner (`85bfa2b`)

`tools/apply-migration.js` reproduces the Supabase SQL editor's behaviour —
**each statement on its own connection**, no shared transaction — so a migration
can be verified before dan runs it. Its splitter tracks line comments, quoted
strings and `$$` bodies, after an earlier version tore a statement on a
semicolon inside a comment.

Permission is deliberately narrow: `Bash(node tools/apply-migration.js:*)`, not
`node` in general. The credential lives in gitignored `.env.local`.

## Mistakes worth recording

**I introduced a regression and then measured my way out of it.** The v0.79.0
work put `destination` on dan's ski circle through `INTEREST_ALSO`, which is
what let a Leros beach through in the first place. The lesson is in the fix:
widening is right for classifying an item and wrong for deriving a circle.

**Three times I named a cause before measuring, and twice the thing was not
broken.** The pattern from 23–24 Aug repeated. What broke it each time was
running a query instead of reasoning from the schema.

**A guard that passes for the wrong reason.** `beta-strip-sim` has one
assertion — that `apple-mobile-web-app-capable` is `yes` — which passes on the
control too. It is labelled `[precondition]` in the output rather than removed,
because it is the reason the two safe-area assertions exist. Anything not so
labelled must fail on `--old`.

**I reconstructed `send_rec_to_member` from a screen fragment** and lost the
`not_authenticated` guard, changed a `not found` check to a null check, and
dropped two fields from the return. `0047` is generated from `0031`'s own text
by `build_0047.py` with four additions, and the diff was shown to prove it.
Never retype a live function from memory.

   `web/index.html:6693` inserts without clearing. Harmless while the sweep

5. **72 of 153 canonicals have no `kind`** and are invisible to the sweep and to
   category learning until something re-enriches them. Deliberate: producers
   fixed, rows left.
6. **Identity Tier 1 needs a discriminator** before the three dropped triggers
   are armed. `primary_category` does not work — `other` is the fallback.
   Normalised name **plus exact location** gets all five live collision groups
   right. Not needed for beta.

   foreign key except `owner_id`, so no poison vector.
8. **`docs/BETA-SMOKE-TEST.md` has never been run end to end.** Every piece has
   been seen working individually; never all in one pass.
